# Исходное задание, права и границы публикации

Основа — предоставленные пользователем положение HackAlem и кейс «ИИ-ассистент для чата на сайте ekt.kz» с отдельным документом доступа к API. Исходные документы не включены в репозиторий: документ доступа содержит секрет. Их текст использован для анализа требований, а указания по новой разработке получены от пользователя.

## Применимые ограничения

| Материал / требование | Принятое решение |
| --- | --- |
| Кейс, раздел 6: разрешены анонимизированные или синтетические данные для демонстрации | В репозитории только явно синтетические примеры. Разрешение свободно публиковать реальный каталог, фото и сертификаты не установлено. Basic Auth не является лицензией. |
| Положение 5.4.4–5.4.6: сторонние компоненты и соблюдение прав | Зависимости раскрыты в манифестах и THIRD_PARTY_NOTICES; чужие проекты и предметные решения не копировались. |
| Положение 6.1.2–6.1.4: широкие права организатора на результаты хакатона | Это не разрешение участнику распространять данные партнёра. Новая разработка после хакатона не выдаётся за конкурсную сдачу. Нельзя из этих пунктов заключать, что все исключительные права переданы. |
| Положение 6.1.5–6.1.7: законность материалов и конфиденциальность, в том числе после завершения | Реальные данные и секреты остаются локально; применимость дополнительных NDA и соглашений по предоставленным файлам установить нельзя. |
| Кейс, раздел 9: подтверждение корзины, достоверность, приватность | Явное подтверждение, серверная проверка цены/остатка, отсутствие платёжных данных, объяснения правил замен. |

Собственный код и синтетические примеры можно показывать в этом публичном репозитории по указанию автора проекта. На материалы поставщика и веса модели права этим репозиторием не предоставляются. Модель не дообучалась на закрытых данных. Исходные DOCX, реальные ответы API, пользовательские каталоги, фото, диалоги, БД, резервные копии, `.env` и производные модели/индексы не публикуются.

## Технические требования кейса

Товарный диалог по артикулу и характеристикам; цена, наличие и характеристики из источника; объяснимые альтернативы при отсутствии позиции; условия покупки; разбор спецификаций и изображений; подтверждённое изменение корзины; ссылка на корзину; воспроизводимый запуск и README. Обязательного языка программирования или обучения собственной модели в материалах не обнаружено. Казахский в кейсе опционален; в этом проекте RU/KK/EN и темы реализуются по запросу пользователя.

Реальный API документирует чтение списка и карточек. Контракт корзины, резерва, заказа, SLA и частоты запросов не предоставлен. В выборочной проверке не установлена однозначная семантика валюты, единиц, кратности и сертификатов. Поэтому реализована собственная локальная корзина, а импорт из ekt.kz доступен только для просмотра. Из требования «хотя бы один аналог» не следует право выдумывать совместимость: при недостатке данных результат пустой.
