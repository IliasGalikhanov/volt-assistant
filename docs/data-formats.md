# Входные данные

Все примеры в `frontend/public/examples` синтетические. Источник выбирается явно; его каталог, история, задания и корзина изолированы от других наборов данных.

## Спецификация

CSV UTF-8 (разделитель запятая или точка с запятой), первый лист XLSX, либо JSON:

```csv
query,quantity
DEMO-MCB-001,3
DEMO-CBL-002,10
```

```json
[{"query":"DEMO-MCB-001","quantity":3}]
```

В первой колонке допускается артикул или описание, во второй — целое количество 1..1 000 000. Заголовок `sku`, `query` или `артикул` пропускается. Максимум 500 строк. Автосопоставление выполняется по точному артикулу; другие строки выбираются вручную из каталога.

DOCX и текстовый PDF: отдельная строка `DEMO-MCB-001 3 pcs`, `DEMO-CBL-002 10 м` или двухколоночная таблица Word. Это ограниченный парсер строк, не универсальное понимание произвольной сметы. Нераспознанные строки свободного текста могут быть пропущены: сверяйте результат с оригиналом. PDF обрабатывает локальный Poppler. Изображения JPEG/PNG отправляются только настроенной локальной Ollama. При отсутствии количества модель предлагает 1 для проверки человеком.

## Каталог

JSON — массив товаров. CSV/XLSX — таблица с обязательными колонками:

`sku,name,category,price_minor,currency,unit,step,stores,attributes`

- `price_minor`: положительное целое число тиынов, например 218000 = 2180 ₸; `currency`: `KZT`.
- `unit`: `pcs` или `m`; `step`: положительное целое количество в партии. Никакой скрытой конвертации ампер, метров или упаковок.
- `stores`: JSON-объект, например `{"central":100,"north":25}`.
- `attributes`: JSON-объект строковых значений. В CSV JSON-ячейки нужно экранировать по правилам CSV.
- `category`: `breaker`, `cable`, `lamp` или другая категория для поиска без правил замен.
- Опционально в JSON: `names` с `ru`, `kk`, `en`, `certificate` (HTTPS-ссылка), `source_url`.

Для других названий колонок в UI задайте JSON-сопоставление канонического имени с заголовком файла, например `{"sku":"Артикул","name":"Наименование"}`. Неуказанные имена остаются каноническими. Импорт — сначала проверка всех строк и предпросмотр, затем отдельное подтверждение. Ошибка не меняет действующий каталог. Повторное подтверждение одного задания не создаёт дубль.

Для правил замен нужны все поля соответствующей категории:

| Категория | Обязательные совпадающие характеристики |
| --- | --- |
| breaker | current_a, poles, curve, voltage_v, breaking_ka, mount |
| cable | section_mm2, cores, material, voltage_v, fire_class |
| lamp | power_w, base, voltage_v, temperature_k, shape, dimmable |

Значения сравниваются как точные строки без инженерных предположений. Отличающиеся остальные свойства показываются отдельно. Проверка этих полей — ограниченное правило кандидатов, а не заключение о полной электрической совместимости.

## Хранение и экспорт

Файл ограничен 10 MiB, каталог — 10 000 товаров. Максимум 30 заданий на браузерную сессию; удаляйте ненужные вложения через UI. Результаты обработки и ошибки сохраняются в PostgreSQL. Отредактированная форма проверки пока живёт в памяти страницы; предложение и подтверждённая корзина сохраняются на сервере.

Экспорт CSV/XLSX содержит артикул, название, количество, единицу, склад, цену и сумму в целых тиынах. CSV экранирует начальные символы формул. Каталог и вложения доступны по cookie сессии; это не публичные файлы.
